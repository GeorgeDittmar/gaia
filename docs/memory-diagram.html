— MEMORY TYPE CHARACTERISTICS —

🧠 Semantic Memory

What the user knows
Facts, concepts, preferences, domain knowledge.
Confidence scoring & autodistillation.
FTS5 full-text search on content.
Source-tracked: user / agent / conversation / distillation.

📖 Episodic Memory

What happened
Time-indexed event records. Full conversation transcripts.
Tool calls, errors, corrections, MCP events.
Retention policy: compress & prune old episodes.
Grouped by conversation_id.

🔧 Procedural Memory

How to do things
Skills, routines, policies, prompt templates.
YAML/JSON on disk + SQLite index.
Safety-gated: safe / caution / danger.
Hot-reloadable without restart.

🔒 Audit Log

Action trail (metadata only)
Append-only, encrypted at rest.
Logs what happened, not what was said.
Full content → episodic memory instead.
Exportable as signed JSONL.

— STORAGE BACKENDS —

🗃️ SQLiteMemoryStore (v1 default)

Local SQLite database. FTS5 virtual tables for full-text search.
SQLCipher encryption when encrypted: true.
ACID transactions, zero external dependencies.
Tables: semantic_facts, episodic_events, procedure_entries, audit_log

☁️ RedisMemoryStore (planned v2)

In-memory with disk persistence. RediSearch for full-text.
HNSW vector indexing for semantic similarity.
EXPIRE TTL for retention policy enforcement.
Multi-device sync via Redis Cloud or self-hosted.

📁 FileStore (dev / lightweight)

JSON/YAML files on disk. No database needed.
Human-editable, git-versionable.
FTS5 → grep/ripgrep fallback.
Ideal for development and single-device use.
